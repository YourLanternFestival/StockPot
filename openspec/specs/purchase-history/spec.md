# 采购单历史记录

## 概述
采购单每日清空，保留最近3天数据供回溯查阅。历史记录通过侧边栏入口查看，小所模式下按"每日一卡、所内分割"布局展示。

## 数据生命周期

### 需求：每日清空
系统应在每天首次打开时自动清空采购单页面的显示内容。

#### 场景：跨天清空
- 假设 用户昨天使用过采购单并保存了数据
- 当 用户今天打开应用
- 那么 采购单页面显示为空（不加载昨天的数据）
- 且 数据库中的历史记录保留，可通过"历史采购"入口查看

### 需求：3天保留期
系统应保留最近3天的采购单数据供查阅。

#### 场景：自动清理
- 假设 存在4天前的采购单数据
- 当 应用启动
- 那么 自动删除超过3天的记录（按 created_at 日期判断）

#### 场景：清理与查询的字段关系
- 清理逻辑基于 `created_at`（记录入库时间）
- 历史查询基于 `receive_date`（到货日期）
- 两者可能不同（如用户提前录入明天的采购单）
- **设计决策**：保留期内只要 `created_at` 未过期，无论 `receive_date` 是哪天都可查到；`created_at` 过期后记录被删除，即使 `receive_date` 还在未来

### 需求：日期绑定
所有采购单数据（包括联华和厨房）都应绑定保存日期。

#### 场景：保存时记录日期
- 假设 用户在2026-06-07保存采购单
- 当 保存操作完成
- 那么 所有记录的 `created_at` 字段为当天日期（自动生成）
- 且 `receive_date` 为用户选择的到货日期（可能与 created_at 不同）
- 且 settings 表的 `last_purchase_date` 键值更新为 "2026-06-07"

## 历史查看

### 需求：侧边栏入口
系统应在侧边栏提供"历史采购"入口。

#### 场景：菜单位置
- 假设 用户查看侧边栏
- 当 导航菜单渲染
- 那么 "历史采购"位于"采购单"和"询价管理"之间

### 需求：按日期查看
历史采购页面应支持按日期查看最近3天的数据。

#### 场景：日期切换
- 假设 用户进入历史采购页面
- 当 页面加载
- 那么 显示最近3天的日期标签（如 06-07, 06-06, 06-05）
- 且 默认选中最近一天
- 且 日期来源为 `getPurchaseHistoryDates` 返回的 DISTINCT receive_date，LIMIT 3

### 需求：只读展示
历史记录为只读，不支持编辑。

#### 场景：展示格式
- 假设 用户查看某天的历史记录
- 当 数据渲染
- 那么 以表格形式展示：序号、品名、规格、单价、数量、单位、金额、备注
- 且 每个分组可展开/折叠（默认折叠）
- 且 不可编辑，仅供查阅和核对

### 需求：金额计算
历史记录应展示每条记录的金额和分组小计。

#### 场景：厨房商品单价取值
- 假设 厨房采购单中某品名的单价
- 当 保存时，单价 = 询价原始价 × discount1_rate（由 `selectAutocompleteItem` 计算后存入 DB 的 `unit_price` 字段）
- 当 历史记录展示
- 那么 直接使用 DB 中的 `unit_price` 和 `amount` 字段（保存时已计算好）
- 且 展示小数位数遵循 `APP_SETTINGS.price_decimals` 设置

#### 场景：联华商品单价取值
- 假设 联华商品的单价
- 当 保存时，单价 = `lianhuaItems.price`（导入时已是盛销折扣后的价格，不再乘 discount1_rate）
- 当 历史记录展示
- 那么 直接使用 DB 中的 `unit_price` 和 `amount` 字段
- 且 展示小数位数遵循 `APP_SETTINGS.price_decimals` 设置

#### 场景：矩阵模式保存的数据
- 假设 数据通过矩阵模式保存
- 当 `saveMatrixData` 执行
- 那么 `unit_price` 写入 0，`amount` 写入 0
- 当 历史记录展示这些数据
- 那么 单价和金额均显示为 0（矩阵模式设计如此，不额外计算）
- 且 若需要矩阵模式的历史金额统计，需在保存时从询价表反查价格并填充（当前不实现，标记为未来优化）

#### 场景：小所模式金额统计
- 假设 用户查看小所模式某天的历史
- 当 数据渲染
- 那么 每个小所区域展示厨房小计、联华小计、该所合计
- 且 页面底部展示当日所有小所的总计
- 且 小计 = 该分类下所有记录的 amount 之和，使用 `toFixed(price_decimals)` 格式化

- 假设 渲染小所分割行

- 假设 渲染小所卡片
- 当 排列小所
- 那么 按 `APP_SETTINGS.small_canteens` 数组的顺序排列

- 假设 某小所当天只有联华加购，无厨房数据
- 当 渲染该小所
- 那么 联华表格正常展示
- 且 厨房区域不显示
- 且 该所合计 = 联华小计

#### 场景：厨房和联华日期不同
- 假设 寿昌厨房数据的 receive_date 为 2026-06-10，联华数据的 receive_date 为 2026-06-09
- 当 用户查看 2026-06-09 的历史

- 当 用户查看 2026-06-10 的历史
- 那么 寿昌区域只显示厨房申购（联华数据在 06-09 的卡片中）
- **设计决策**：按 receive_date 分日展示，不要求厨房和联华日期一致

## 联华加购数据流

### 需求：联华加购保存到 purchase_orders
联华加购数据应保存到 purchase_orders 表，与厨房数据统一管理。

#### 场景：保存联华加购
- 假设 用户在小所模式下为寿昌添加联华加购
- 当 用户在弹窗中点击"保存"
- 那么 数据追加到 DOM 中的联华日期分组表格（不写入 DB）
- 当 用户点击"保存所有"或切换页面触发自动保存
- 那么 数据写入 purchase_orders 表
- 且 source = "寿昌-联华"
- 且 receive_date = 用户选择的到货日期
- 且 unit_price = lianhuaItems.price（导入时已是盛销折扣价）
- 且 amount = unit_price × quantity

### 需求：联华加购在历史中可见
联华加购数据应与厨房数据一同在历史记录中展示。

#### 场景：查看包含联华的历史
- 假设 寿昌当天有厨房数据和联华加购数据
- 当 用户查看该天历史
- 那么 寿昌区域内显示"厨房申购"和"联华加购"两个表格
- 且 数据均来自 purchase_orders 表，按 receive_date 查询

### 需求：数据源识别规则
历史页面应根据 source 值正确区分厨房和联华数据。

#### 场景：小所模式
- source 格式为 `{所名}-厨房` → 归入该所的厨房区域
- source 格式为 `{所名}-联华` → 归入该所的联华区域

#### 场景：多食堂模式
- source 格式为 `{食堂名}-厨房` → 归入该食堂的厨房区域
- source 格式为 `{食堂名}-联华` → 归入该食堂的联华区域

#### 场景：默认模式
- source = "联华" → 联华超市
- source = "{食堂名}食堂厨房" → 厨房（如 "洋安食堂厨房"）
- source = "{食堂名}面点房" → 面点房（如 "洋安面点房"）

### 需求：联华加购不覆盖原有数据
反复打开联华加购弹窗并保存，应追加数据而非覆盖。

#### 场景：追加联华加购
- 假设 寿昌已有2条联华加购记录
- 当 用户再次打开联华加购弹窗并添加3条
- 那么 寿昌联华数据变为5条（2条旧 + 3条新）
- 且 旧数据不丢失

#### 场景：联华加购弹窗显示已有数据
- 假设 寿昌当天已有联华加购数据
- 当 用户打开寿昌联华加购弹窗
- 那么 弹窗中应显示已有的联华加购清单
- 且 用户可在此基础上继续添加

## 其他模式历史布局

### 需求：默认模式和多食堂模式保持不变
默认模式和多食堂模式的历史展示逻辑不变，按 source 分组展示。

#### 场景：默认模式
- 假设 当前食堂模式为"默认"
- 当 查看某天的历史
- 那么 按 source 分组，每组独立卡片

#### 场景：多食堂模式
- 假设 当前食堂模式为"多食堂"
- 当 查看某天的历史
- 那么 按 source 分组，每组独立卡片

### 需求：历史布局基于当前模式
历史页面的展示布局基于当前的食堂模式设置，而非保存时的模式。

#### 场景：模式切换后查看历史
- 假设 用户在小所模式保存了数据（source 为 "寿昌-厨房" 等）
- 当 用户切换到默认模式后查看历史
- 那么 按默认模式的布局展示（每 source 独立卡片）
- 且 小所数据通过兜底逻辑出现在列表末尾，不丢失

## 技术实现

### 数据库
- 复用 purchase_orders 表
- 按 `receive_date` 日期筛选历史数据
- 启动时清理 `created_at < (今天 - 3天)` 的记录
- `getPurchaseHistoryDates` 返回 `LIMIT 3`（与保留期对齐）

### 设置
- `last_purchase_date`：记录最后一次保存采购单的日期
- `discount1_rate`：盛销折扣率，厨房商品保存时已乘折扣后存入 DB
- `price_decimals`：价格小数位数，用于金额展示的 `toFixed()` 格式化

### 数据源区分
参见"数据源识别规则"章节。核心规则：
- 小所/多食堂模式：source 格式为 `{名称}-厨房` 或 `{名称}-联华`
- 默认模式：source 为 `"联华"`、`"{名}食堂厨房"`、`"{名}面点房"`

### 金额计算
```
# 厨房商品（保存时已计算）
unit_price = DB 中的 unit_price（= 询价原始价 × discount1_rate）
amount = DB 中的 amount（= unit_price × quantity）

# 联华商品（保存时已计算）
unit_price = DB 中的 unit_price（= lianhuaItems.price，导入时已是折扣价）
amount = DB 中的 amount（= unit_price × quantity）

# 展示格式
展示金额 = amount.toFixed(price_decimals)
```

### 矩阵模式特殊处理
矩阵模式保存时 `unit_price=0, amount=0`。历史页面直接展示 DB 中的值，不额外计算。

### 已知限制
- 联华加购弹窗"显示已有数据"功能待实现
- 矩阵模式保存的数据在历史中单价和金额为 0

### 页面
- `renderer/history.js`：渲染逻辑
- `renderer/index.html`：history 区域
